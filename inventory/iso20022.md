# ISO-20022 Public Hosts

This document records the publicly reachable SumUp hosts related to the ISO‑20022/SEPA payment rail that were identified as lacking a Web Application Firewall (WAF) front‑end.

## Hosts

| Hostname | IP Addresses | Service | Notes |
|----------|--------------|---------|-------|
| `iso20022.sumup.com` | 52.19.224.211, 54.155.143.33, 63.33.227.130 | Istio Envoy mesh gateway (port 80/443) | Public entry point without Cloudflare or other WAF. Returns `400 Bad Request` for `/` and `/messages`. Header `x-envoy-decorator-operation` present. |
| `iso20022-edge.sumup.com` | 52.19.224.211, 54.155.143.33, 63.33.227.130 | AWS ELB (awselb/2.0) | Returns `404 Not Found`. Shares the same IP set as the Istio gateway but routes to a different upstream service. |

## Context

Both hostnames resolve to the same set of AWS EU‑West‑1 IP addresses but expose different upstream services. The `iso20022.sumup.com` endpoint is reachable directly from the internet without any CDN or WAF protection, which is atypical for SumUp's external surface. The gateway appears to forward arbitrary paths to an internal `br-terminals` service on port 3000, raising potential SSRF concerns if the downstream service processes caller‑controlled payloads.

## Action Items

- Review the Istio gateway configuration to ensure proper request validation and WAF protection.
- Consider adding Cloudflare or another edge security layer in front of `iso20022.sumup.com`.
- Verify that the downstream `br‑terminals` service does not perform outbound fetches based on request data.
